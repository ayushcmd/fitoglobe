# Support for FitoGlobe

Thanks for using FitoGlobe! This guide explains where to ask questions, report problems, and suggest improvements.

## Before opening an issue

- Check the [README](README.md) for features, local setup, and environment configuration.
- Review [existing issues](https://github.com/ayushcmd/fitoglobe/issues) to see whether your question or problem has already been reported.
- If you are contributing code, read [CONTRIBUTING.md](CONTRIBUTING.md).

## Where to get help

| You need help with... | Where to go |
| --- | --- |
| Using the app, setup, or configuration | [Open a GitHub issue](https://github.com/ayushcmd/fitoglobe/issues/new) |
| A reproducible bug | [Open a GitHub issue](https://github.com/ayushcmd/fitoglobe/issues/new) |
| A feature idea or improvement | [Open a GitHub issue](https://github.com/ayushcmd/fitoglobe/issues/new) |
| Contributing or development workflow | [CONTRIBUTING.md](CONTRIBUTING.md) |
| Suspected security vulnerability | Follow [SECURITY.md](SECURITY.md) for **private reporting** |
| Community conduct complaint | Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) |

GitHub Issues is the current public support channel for this repository. GitHub Discussions is not currently enabled, and there is no dedicated public support inbox listed here.

## How to write a useful support request

Please include, where applicable:

1. **Summary:** what you are trying to do and what went wrong.
2. **Expected and actual behavior:** what you expected versus what happened.
3. **Steps to reproduce:** a short numbered sequence, if there is a bug.
4. **Environment:** browser and version, device/OS, app URL or local development setup.
5. **Relevant details:** sanitized error messages, screenshots, or console output.
6. **Troubleshooting attempted:** what you already tried.

For frontend problems, mention whether you are using the [hosted app](https://fitoglobe.vercel.app) or a local Vite development server. For backend problems, note whether PostgreSQL and the API are running, but **never share connection strings or credentials**.

## Privacy and security

**Do not post** passwords, API keys, access tokens, JWTs, personal health information, private fitness or nutrition records, or other people's data in public issues. Remove identifying details from screenshots and logs.

If the issue could expose data, bypass authentication, or affect account security, use the [private vulnerability reporting guidance](SECURITY.md) instead of a public issue. The security policy explains how to request a private contact channel if private vulnerability reporting is unavailable.

## Response expectations

This project is maintained on a best-effort basis. Public issues are welcome, but no guaranteed reply or fix timeframe is offered. Please avoid opening duplicate issues or repeatedly tagging maintainers.

For contributions and pull requests, see [CONTRIBUTING.md](CONTRIBUTING.md).

Thank you for helping make FitoGlobe better.
